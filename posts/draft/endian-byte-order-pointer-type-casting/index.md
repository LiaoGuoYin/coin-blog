## 大端、小端字节序介绍

注意，这里讨论的是**字节序列**。这种纠结通常发生在某个变量占有多个字节时，不同系统对这串字节的解读顺序不一样。

大端小端的说法不存在于字节内部。比如 `11010001` 就不用纠结是 `1101 0001` 还是 `0001 1101`，它就是 1 Byte（8 bits），无所谓大小端。因为字节是计算机计算和存储的基本单位，一个 ASCII 字符也就 1 字节，粒度再缩小意义就不大了。

大小端的 **教科书定义**：在大多数实际应用中，网络传输的字节序用大端，计算机内部存储用小端。

> 宇节的排列方式有两个通用规则。例如，将一个多位数的低位放在较小的地址处，高位放在较大的地址处，则称小端序；反之则称大端序。在网络应用中，字节序是一个必须被考虑的因素，因为不同机器类型可能采用不同标准的字节序，所以均按照网络标准转化。 -WikiPedia

**讲点人话**：计算机中常见存储方式是小端，符合人类阅读和计算习惯的方式更像大端。

所谓符合人类阅读和计算的方式，就是：**高地址索引位在前，低地址索引位在后**。比如：

11010000 00000001 高地址索引位在前
11010000 00000001 对应的二进制为：2^0 + 2^12 + 2^14 + 2^15 = 53249

再说说指针（`*p`）。指针其实就是一种解读方式。指针解引用取值（`*p`）和指针运算（`p+i`）时，都会依赖其类型长度作为步长。所谓改变指针类型，就是改变这个地址的解读方式，也就是改变它解读时的步长。

通过指针类型转换，我们可以非常直接地干涉内存的解读方式。比如一块连续内存里放的是字节序：1 2 3，每个数字代表一个字节。那么通过强转指针类型，可以按一个字节读内存认作一个数，也可以按两个字节读内存认作一个数。

但操作过程中要注意大小端问题。如果忽略这一点，强制转换出来的数可能非常奇怪，甚至让人误以为遇到了野指针或未定义地址块。如何合理利用指针结合大小端解读内存里的数据？举个简单例子：

```c++
char queryBuffer[] = {0 , 0 , 2 , 98};
cout << *((uint32_t*)queryBuffer + 1);
```

解读：
在 C 语言中，charList 会是数组首地址的指针，其值为首地址，接下来第二个值 0 的地址就是索引位更高的地址。而在进行指针类型转换时，第一个 0 会被作为高位读进去，符合人类阅读计算方式，所以默认强转指针后解引用出来像是大端。

`queryBuffer` 是指针，值是数组首地址。因为是 char 类型，按 1 个字节解读，所以 `queryBuffer + 1` 时，步长为 1 字节。`(uint32_t*)queryBuffer` 也是指针，但这里做了指针类型强制转换，会按照 4 个字节解读，也就是 `queryBuffer + 1` 时步长变成 4 字节。由于电脑内部是小端字节序，前四个字节是 `0, 0, 1, 98`。那么 98 会被解读为高位地址：

- 按大端解读：01100010, 00000001, 00000000, 00000000，十进制为1644232704
- 按小端解读：00000000，00000000，00000001，01100010，十进制为354
